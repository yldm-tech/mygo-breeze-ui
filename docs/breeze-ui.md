# Breeze UI for MyGo

`github.com/yldm-tech/mygo-breeze-ui/ui/breeze` draws [MyGo](https://github.com/egoist/mygo)'s native UI widgets as the desktop the app runs on draws its own controls: macOS's on a Mac, Windows 11's on Windows and GNOME's libadwaita controls on Linux.

Its widgets have the names and signatures of package `ui`'s. A view swaps `ui.Button` for `breeze.Button` and keeps everything else: the widgets return `ui.Element`, answer `Clicked`, and take more styles after the call as `ui`'s do.

```go
import (
	"github.com/egoist/mygo/ui"
	breeze "github.com/yldm-tech/mygo-breeze-ui/ui/breeze"
)

func (app *settings) view(c *ui.Context) {
	breeze.Use(c) // the platform's colors and metrics, for package ui's widgets too
	ui.Column(c).Padding(16).Gap(12).Children(func() {
		breeze.Checkbox(c, &app.remember, "Remember me")
		breeze.Switch(c, &app.sync).Label("Sync")
		ui.Row(c).Gap(8).Children(func() {
			breeze.Button(c, "Cancel")
			if breeze.PrimaryButton(c, "Save").Clicked() {
				app.save()
			}
		})
	})
}
```

## Install

```sh
go get github.com/yldm-tech/mygo-breeze-ui
```

It needs MyGo v0.7.4 or later. The gallery shows the three platforms side by side:

```sh
go run ./examples/breeze-ui
```

## Storybook

[The storybook](https://yldm-tech.github.io/mygo-breeze-ui/storybook/) shows every widget as Storybook shows components: stories in a sidebar, each drawn as macOS, Windows 11 or GNOME draws it, or as the three side by side, light or dark, with controls for its arguments and the Go that builds it. It is [`examples/storybook`](../examples/storybook), which runs as a window with `go run ./examples/storybook`; the site's deployment compiles it to WebAssembly (`GOOS=js GOARCH=wasm`), which MyGo draws in the page with WebGL 2. To try the web build locally, build the site, then the storybook into it, and serve `website/dist` under `/mygo-breeze-ui/`:

```sh
bun run site:build
GOOS=js GOARCH=wasm go build -o website/dist/storybook/app.wasm ./examples/storybook
cp "$(go env GOROOT)/lib/wasm/wasm_exec.js" website/dist/storybook/
```

These are drawn by Breeze UI. Their sizes and colors come from the platforms themselves:

- **macOS:** AppKit's semantic colors (`NSColor`) resolved in sRGB on macOS 27.2, and AppKit's own controls rendered at 2x by [`tools/appkit-reference/reference.swift`](../tools/appkit-reference/reference.swift) into an sRGB bitmap in a window drawn as the key window, which writes them as PNGs and prints the values across each control (`-inactive` renders an inactive window's look). Focus rings, the chosen tab's platter and the source list's selection, which AppKit does not render offscreen, were measured from captures of a live key window. A push button's face is `secondarySystemFill`; an unchecked box, a radio button and an off switch are `systemFill`. Run `BREEZE_SCREENSHOTS=<dir> go test ./ui/breeze -run TestScreenshots` for Breeze UI's controls in the same places.
- **Windows 11:** the theme resources of WinUI 3 (`microsoft/microsoft-ui-xaml`, main at cb1b8a6): `Common_themeresources_any.xaml` and the theme resources of Button, ToggleButton, CheckBox, RadioButton, ToggleSwitch, TextBox, ComboBox, Slider, ProgressBar, ProgressRing, SelectorBar, ContentDialog and ToolTip; the dialog's shadow from `DropShadowRecipe.h`; the check mark and chevrons from the path data of WinUI's animated icons (`AnimatedAcceptVisualSource`, `AnimatedChevronDownSmallVisualSource`, `AnimatedChevronUpDownSmallVisualSource`); the ProgressRing's and the indeterminate ProgressBar's motion from `ProgressRingIndeterminate.cpp` and `ProgressBar.xaml`; the two-stroke focus visual from `FocusRectManager.cpp`. These controls were then compared with WinUI 3's own rendering: [`tools/winui-reference`](../tools/winui-reference/Program.cs), an unpackaged WinUI 3 app carrying Windows App SDK 2.6.5 (WinUI 3.3), renders WinUI's Button, accent Button, CheckBox, ToggleSwitch, RadioButton, TextBox, AutoSuggestBox, ComboBox, ToggleButton, Slider, ProgressBar, ProgressRing, SelectorBar, a Hyperlink, a divider, DropDownButton, Flyout and ContentDialog at 2x in the light and dark themes, in Segoe UI Variable and with Windows's default accent forced, where the screenshot test places Breeze UI's, and a fifth set of them held in their PointerOver and Pressed states, which `TestScreenshotsWindowsStates` draws for Breeze UI; it writes PNGs and the frames of every control, its template parts and its text, and the values across it. On Windows 11 26H2 (build 26300) their sizes, radii, borders and fills, at rest, under the pointer and pressed, now match WinUI's within a level or two but for the text. The default accent now takes the shades Windows gives #0078d4 (`#76b9ed` for the dark theme's fill, where a mix read `#7ab9e9`); the tool sets those shades itself, so the render shows where WinUI uses them rather than measuring them. The comparison corrected the inner half of the strokes of check boxes, radio buttons and switches (WinUI's fills reach the middle of a translucent stroke, which reads darker there), the off switch's knob (laid over its track, not over the window), the chosen radio button's dot (11 DIPs of fill inside a ring half over the accent, under the pointer the ring of `CircleElevationBorderBrush`, and pressed a 10-DIP dot without a ring, as the template's `PressedCheckGlyph` covers it), the slider thumb's edge (translucent over the track), the labels of check boxes and radio buttons (5 and 6 DIPs below the top, not centered), the text box's and the ComboBox's padding (the 1-DIP border is inside WinUI's), the chevrons of the ComboBox and DropDownButton (centered on the box, in `TextFillColorSecondary` over the face), the edges of flyouts and of the ContentDialog (over what is behind them, not over their fill), and a disabled checked box (gray, as far as MyGo's half opacity allows).
- **GNOME:** the libadwaita 1.10.0 stylesheet (GNOME 51, with GTK 4.24 and adwaita-icon-theme 51), and the C code of libadwaita and GTK where the stylesheet leaves a value to them: the accent, the switch's and the scale's sizes, the drop-down's check mark, the spinner's arc and the alert's width. Every value was checked against the changes from libadwaita 1.7.6 to 1.10.0; the colors did not change, while popovers, dialog shadows, the alert's hairline and body, the spinner's stroke, the check mark and the sidebar (AdwSidebar, new in 1.9) did. The look was then compared with libadwaita 1.10.0 itself: [`tools/adwaita-reference/reference.py`](../tools/adwaita-reference/reference.py) renders, with GTK 4.24.1, libadwaita 1.10.0 and Adwaita Sans under Xvfb, libadwaita's counterparts of the controls of every screenshot test in the same places, light and dark, at 2x, and prints their bounds. Buttons, check boxes, radio buttons, switches, entries, toggles, linked toggles, drop-downs, scales with and without marks, progress and level bars, toggle groups, text views, alerts, links, separators, toasts, the sidebar, toolbars with their flat and raised buttons, spin buttons, color buttons, rich lists, column and tree lists, expanders and boxed lists match it to the pixel but for the glyphs. Call it once in the view; without it MyGo draws its own toasts.

`Text(c, s, style...)` draws a text in a step of the platform's type ramp: `TextLargeTitle`, `TextTitle`, `TextSubtitle`, `TextHeading`, `TextBody` or `TextCaption`, with `TextSecondary` added by `|` to dim any of them (`breeze.Text(c, "Applies to every window.", breeze.TextCaption|breeze.TextSecondary)`). It is `ui.Text` with the step's size, weight and line height, in the theme's font. The style comes after the text and can be left out: without one it is `TextBody`, which draws exactly what `ui.Text` draws, so `breeze.Text(c, s)` replaces `ui.Text(c, s)` as Breeze UI's other widgets replace theirs. The steps are the ones the three platforms share: a strong body, WinUI's BodyStrong, is `TextHeading`, as macOS's headline and libadwaita's `.heading` are the body in bold too; the subtitle is libadwaita's `.title-4`, since `.title-3` is `.title-2`'s size; libadwaita's `.body`, which only raises a paragraph's line height to 140%, is left to `LineHeight(1.4)`. Dimming is a flag rather than more steps because each platform dims any style the same way: AppKit with `secondaryLabelColor`, WinUI with `TextFillColorSecondary`, both the theme's `TextMuted`, and libadwaita by the label's opacity (`.dimmed`), which Breeze UI sets as `Opacity` on GNOME. A title is plain text to assistive technology, as the platforms' title styles are; `Role(ui.RoleHeading)` and `Level` make it a heading. The name stays `Text` rather than `Label`, which would read as `Element.Label`, the accessible name that Breeze UI's examples set everywhere.

## Platforms

`breeze.Current()` is the platform the app runs on: `Mac` on macOS, `Windows` on Windows and `Linux` elsewhere. Every widget looks it up when it is built.

- `breeze.SetPlatform(breeze.Windows)` makes every window draw another platform's controls, as for screenshots; `breeze.SetPlatform(breeze.Auto)` follows the system again.
- `breeze.Preview(c, p, body)` draws only what `body` builds as platform `p`, in this window. With `ui.Themed(c, breeze.Theme(c, p))` around it, a gallery shows the platforms side by side:

```go
for _, p := range breeze.Platforms {
	breeze.Preview(c, p, func() {
		ui.Themed(c, breeze.Theme(c, p)).Grow(1).Padding(16).Gap(12).Children(func() {
			breeze.Button(c, "Cancel")
			breeze.Switch(c, &app.sync).Label("Sync")
		})
	})
}
```

## Themes

`breeze.Theme(c, p)` returns platform `p`'s theme for the window's appearance: the window background, text, separators and accent of macOS, Windows 11 or GNOME, light or dark. `breeze.Use(c)` sets it for the window with `c.SetTheme`, so package `ui`'s widgets and elements of your own that read `c.Theme()` follow it too.

Like MyGo's default theme it follows the desktop's preferences:

- **Accent color.** The accent the user chose replaces the platform's default (`#007aff`, `#0078d4`, `#3584e4`). On Windows the controls are filled with the shade WinUI uses, darker in the light theme and lighter in the dark one.
- **Higher contrast.** Separators and secondary text are darker in the light theme and lighter in the dark one, and the focus ring is opaque.
- **Text size.** The font size grows with Windows's and GNOME's text scale.

## Limits

- **Inactive windows.** AppKit draws an inactive window's accent controls (checked boxes, chosen radio buttons, on switches, an on toggle, the chosen segment and the default button) in gray. MyGo v0.7.4 does not tell a view whether its window is active, so Breeze UI always draws the key window's look.
- **Liquid Glass surfaces.** Menus, popovers, tooltips and NSAlert's panel are separate windows of macOS 27's glass material, which AppKit does not render offscreen and which could not be captured from a live window either (a popover's window is not listed, a tooltip shows only under the pointer): they are drawn to resemble macOS 26's, not measured.
- **Sizes.** The platforms' controls differ in size: a macOS push button is 24 points high, Windows's 32 and GNOME's 34, and a GNOME scale is 34 pixels high with its padding (28 with marks after it). The same layout is denser on a Mac; size elements around the widgets from the content rather than with fixed heights.
- **Windows and GNOME fidelity.** The macOS look is compared with AppKit's rendering on macOS 27.2, pixel by pixel. The Windows look of the controls of the screenshot test is compared with WinUI 3.3's rendering on Windows 11 26H2 (`tools/winui-reference`); what it could not compare is taken from WinUI's sources: the focus visuals (nothing has the keyboard's focus in the render), the ContentDialog's smoke layer (left out when the dialog is shown in place, as it must be to be rendered at 2x), the drop-down of the ComboBox and other menus, the check mark's stroke (WinUI's animated icon renders without antialiasing there; its area suggests about 1.35 DIPs where the source gives 1.225), and the widgets of the `widgets_*.go` and `drawn_*.go` files but for `PasswordField`, `SplitButton`, `IconButton`, `InfoBar`, `ProgressRing`, `Card`, `ActionRow`, `SwitchRow` and `Text`, which are compared with WinUI's PasswordBox, SplitButton, Button, CommandBar, InfoBar, ProgressRing, CommunityToolkit's SettingsCard and SettingsExpander and the TextBlock styles (and `StatusPage`'s text with the type ramp) in the same way. Of those, what still differs: the bullets of a PasswordBox (MyGo's), the icons of the tests (SVGs, not Segoe Fluent Icons), the informational InfoBar's fill by a level, the text's line height, the header of an `AccordionItem` and the disabled colors (WinUI's disabled icon button reads 245 with a 229 edge and a 157 icon, Breeze UI's at half opacity 247, 238 and 136; a disabled SettingsCard keeps its card). Text is not compared glyph by glyph: WinUI's is DirectWrite's Segoe UI Variable, Breeze UI's is the host's font through MyGo (Segoe UI on Windows), so labels sit where WinUI puts their text box and differ by the fonts' ascents elsewhere; the render lays out in whole DIPs, where WinUI at 200% rounds to half DIPs. The GNOME look is compared with libadwaita 1.10.0's rendering (GTK 4.24.1), pixel by pixel, for the controls of every screenshot test that libadwaita has: those listed under GNOME above. Where GNOME's look depends on text, Breeze UI follows the font it is given rather than Adwaita Sans, so a control after a label moves with the label's width. libadwaita 1.10.0 draws a GtkLevelBar's `.low` block in the accent color, a later rule of `_level-bar.scss` overriding the warning color; `Meter` keeps the warning and error colors for its levels, as GtkLevelBar has no level that is bad when high. Some values are inferred rather than read: the padding of an accent button and the line height of 14-pixel text on Windows, the ProgressRing's starting angle, the ComboBox's item height, the BreadcrumbBar's chevron (a Segoe Fluent Icons glyph), and the spacing of toggles in a `ToggleGroup`, as WinUI has no joined toggles. Windows's default accent takes the shades Windows gives it; for a custom accent the shades (link colors and fills) are mixes that come within a few levels of the default accent's.
- **What only MyGo draws.** The arrows of `Stepper`, the search field's magnifying glass (at the start of the field, where WinUI's AutoSuggestBox puts its query button at the end), the caret (in the accent on every platform, where macOS 27 draws a 2-point accent caret and GNOME the text color) and the rows of `PopoverMenuButton`'s menu (their height and padding; their corners follow the theme's radius, 13 on GNOME against libadwaita's 9) are MyGo's, and on GNOME that menu has no arrow pointing at its button, where GtkMenuButton's popover has one.
- **Dialogs.** An alert shows no icon: NSAlert shows the app's icon above its title, which a view cannot reach. GNOME's alert stacks its buttons when they do not fit side by side; Breeze UI keeps them in a row. On macOS the corner radius and the alert's colors are measured from NSAlert's window; the hairline around a dialog and its shadow are drawn to resemble AppKit's, not measured.
- **Scroll bars.** MyGo shows a container's thumb while the pointer is over the container or drags it, 3 DIPs in from the edge, at least 24 long, 2 DIPs wider while dragged, with no track or arrows. The platforms differ: macOS's overlay scroller (17 points wide, measured with `NSScroller.scrollerWidth` on macOS 27.2) paints a 7-point knob with a faint 1-point outline 1 point in from its edge, shows it while the view scrolls and widens it under the pointer; WinUI's ScrollBar is a 2-pixel indicator that grows after 0.4 seconds under the pointer into a 12-pixel bar with a track and small arrow buttons and contracts 2 seconds after it leaves; GNOME's overlay scroll bar is a 3-pixel slider 4 pixels in from the edge that grows into an 8-pixel slider over a 10% trough under the pointer, at least 40 long, with a 1-pixel outline.
- **Errors on text fields.** The platforms' text fields draw their own borders and focus, so a field's `Error` does not turn its border red as `ui`'s fields do.
- **Icons and fonts.** Breeze UI ships no SF Symbols, Segoe Fluent Icons or Adwaita icons: check marks, chevrons and arrows are drawn as paths, and the search field's magnifying glass is MyGo's. Text uses the system's font (`Font: ""`).
- **Type ramp.** MyGo lays out a line as the font's ascender and descender, without the leading AppKit adds, so on macOS every text, `ui.Text`'s and `Text`'s, is a little shorter than AppKit's line height (15.3 points for the body's 16, 30.6 for the large title's 32); `Text` keeps MyGo's spacing on every step so that the body stays `ui.Text`'s. On Windows MyGo draws Segoe UI (its `system-ui` in `dwrite_windows.go`) rather than Segoe UI Variable, WinUI's font on Windows 11, and so without that font's optical sizes: the glyphs differ a little in shape and width, not in size. WinUI's Subtitle, Title and TitleLarge trim their first glyph's side bearing (`OpticalMarginAlignment` TrimSideBearings), which MyGo cannot, so they start that bearing further right than WinUI's. WinUI's Display (68) and BodyLarge (18) steps, macOS's title3, callout, subheadline and footnote and libadwaita's `.title-3`, `.caption-heading`, `.document`, `.monospace` and `.numeric` have no step of their own; `FontSize`, `FontWeight`, `Font("monospace")` and `FontFeatures("tnum")` on the returned text give them.
- **Toolbars.** Buttons built inside a `Toolbar` take its look, and so do buttons in a `Popover` or `Modal` opened from inside the toolbar's build, as MyGo's own toolbar look reaches them too. On macOS adjacent image items join into one platter from the second frame, as joining reads the first frame's layout. The overflow button MyGo adds when items do not fit is MyGo's.
- **Parts MyGo draws inside a widget.** Without a base for them, these stay MyGo's in the platform's theme: the accordion's headers (SwiftUI puts the chevron before a regular-weight title, an Expander's header is 48 high, an AdwExpanderRow 55 high with its separator, a regular-weight title and an accent arrow when open, its rows on `card_shade_color` at 50%), the popup of `Combobox` (highlighted in the accent, not the platform's menu), the chips of `TokenField` (gray, not NSTokenField's flat blue tokens), the headers of `Table` and `OutlineTable`, the arrow of `TreeItem`, MyGo's fixed row geometry (a `Table` row is at least 32 high where AppKit's is 24, and `Outline`'s content starts about 13 points right of AppKit's), the room after the date of `DateInput` on macOS (14 DIPs where MyGo's icon was), the colon of `TimeInput` (muted, where AppKit draws it in `labelColor`) and the dividers of WinUI's TimePicker. The Windows label of `Field` and the GNOME legend of `Fieldset` are drawn over MyGo's at their platforms' weights: the Windows label does not dim when only its control is disabled.
- **Text inside a sub-theme.** The panes of the `Split` family are built in a theme of their own, so their text takes the theme's color, size and font rather than those around them.
- **Shared outline states.** `Outline` and `OutlineTable` set an `OutlineState`'s `Indent` to the platform's when it is 0; a state shared by several `Preview`s keeps the first platform's.
- **Pressed rows.** `List`, `Table`, `Outline` and `GridView` draw chosen and hovered rows as each platform does but not pressed ones, as MyGo's rows do not report a press.
- **Rating's layout.** `Rating` returns `ui.Rating`'s row inside a column of its own, which takes the place in the parent's layout: give a margin or a grow to an element around it rather than to the row.
- **Radio groups.** `RadioGroup` sets the platform's spacing but shows no header: its `Label` names it for assistive technology only, where WinUI's RadioButtons shows its Header above the buttons. Across a row, WinUI's RadioButtons gives every button the width of the widest; Breeze UI's keep their own widths, at least 120 as a RadioButton's.
- **Password fields.** The bullets are MyGo's (U+2022 in the field's font), smaller than AppKit's 5.5-point dots 8 points apart (measured from NSSecureTextField's render) and WinUI's PasswordChar (U+25CF); GTK's are its invisible character, U+25CF where the font has it (`find_invisible_char` in `gtktext.c`). NSSecureTextField's and GtkPasswordEntry's caps-lock indicator is not drawn, as MyGo does not tell a view whether Caps Lock is on. WinUI's RevealButton also reveals the text while assistive technology toggles it (the Toggle pattern); Breeze UI's reveals it while the pointer presses it or Alt+F8 is held. On GNOME the peek icon stays off, as GtkPasswordEntry's default; an app wanting AdwPasswordEntryRow's has to draw it.
- **Split buttons.** Both parts are Tab stops, as in GTK, where WinUI's SplitButton takes the focus once and opens its menu with Alt+Down or F4 (`SplitButton.cpp`), and the focus ring goes around the part that has it. Styles given to what `SplitButton` returns apply to the main part only, but for `Disabled`, which the arrow part takes from it in the next frame; give margins and sizes to an element around it. WinUI's FlyoutOpen state (both parts pressed while the menu shows) is not drawn: the system's menu does not tell the view it shows.
- **Settings rows.** On Windows a `SwitchRow` toggles on a click anywhere on its card, as AdwSwitchRow does, where Windows Settings toggles only on its ToggleSwitch, and its On and Off text is English, as Breeze UI cannot read MyGo's translations. Content other than rows built with rows in a `Card`, a `Fieldset` or an `AccordionItem` sits in the list without its padding: build rows alone there. Rows join the `Card`, `Fieldset` or `AccordionItem` whose fn builds them even inside another element there, such as a `Collapsible` or a `ui.Row`: build them directly in it. A disabled row alone fades its own box with its content at MyGo's half opacity, where AppKit and libadwaita keep the section or the boxed list as it is and dim only the row's content (SwiftUI's grouped form even keeps the title's color, measured on macOS 27.2). The padding of a GNOME card without rows, the gap between the controls at a row's end on macOS and Windows and the inset of the rows of a `Card` on Windows (16, as a Card has neither a SettingsExpander's icon nor its chevron) are inferred; on Windows rows narrower than 476 DIPs put their controls below their text, as SettingsCard does, deciding it from their width in the previous frame.
- **Tooltip and Description.** `Tooltip` sets the anchor's Description to its text, replacing one given before it, as package `ui` offers no way to read it: give a Description of your own after `Tooltip`.

## What MyGo would need

MyGo v0.7.4 is the latest release. These additions to it, in the style of its existing bases (`CollapsibleBase`, `TabsBase`, `ToastBase`), would let Breeze UI draw what it cannot yet:

- **Disabled colors.** A per-theme or per-element switch for the half opacity of disabled elements (`paint.go`, with `Element.Opacity` clamped to 1), so that AppKit's and WinUI's disabled colors can be drawn while GNOME keeps the halving.
- **Theme tokens.** The focus ring's width, offset and an inner stroke (AppKit's ring is 3.5 points flush outside the shape, libadwaita's 2 pixels inside it, WinUI's two strokes); the caret's color and width; the selected text's color; the scroll bar's inset, width under the pointer, track, outline and minimum length; the label weight of `Field` and the legend weight of `Fieldset`; a badge's text size; `Themed` without resetting the inherited text style.
- **Scroll bars.** A way for an element to draw its scroll container's bars, as `Scrollbars(false)` hides them, while MyGo keeps their behavior (MyGo's public `ui.Scrollbar` and `Painter.Scrollbar`, for views that scroll themselves, paint the same fixed thumb and take only `ScrollbarState{Dragging, Color}`, so they cannot draw another look either): a callback such as `Element.DrawScrollbars(func(p *Painter, bar ScrollbarPaint))` given, for each bar, its orientation, track and thumb boxes, whether the pointer is over the bar itself (not only the container), over the thumb, pressing or dragging it, and how long ago the content last scrolled, together with per-element geometry that MyGo's hit testing and thumb arithmetic follow: the bar's width at rest and under the pointer, its inset from the edge, the thumb's least length, and optional arrow buttons that step by a line and repeat while held. With it Breeze UI could draw macOS's overlay knob (7 points with its outline, appearing while scrolling and widening under the pointer), WinUI's ScrollBar (the 2-pixel indicator expanding into a 12-pixel bar with its `AcrylicInAppFillColorDefault` track, 8-pixel arrow glyphs and corners of 3, `ScrollBar_themeresources.xaml`) and GNOME's overlay scroll bar (the 3-pixel slider growing to 8 over a 10% trough, at least 40 long, `_scrolling.scss` of libadwaita 1.10.0), and draw `Scroll`, `ScrollBoth` and `ScrollHorizontal` itself.
- **Bases.** `AccordionItemBase` (the headers with MyGo's Up, Down, Home and End and its focus ring), `RangeSliderBase` (or `Element.NamedAfter`, so knobs are named after the slider, and a way to read which knob has the focus), `NumberInputBase` and `DecimalInputBase` (with MyGo's localized errors), `CalendarBase` (with `Browse`), `FindBarBase`, `ColorPickerBase`, `EditableTextBase`, `DateInputBase` and `TimeInputBase` (the icon, the segments and their places), `CheckboxGroupBase` (so `ui.Checkbox` boxes count too), and a `MenuBase` or a menu style for drawn menus and the popups of `Combobox` and `Autocomplete`.
- **Rows and cells.** `ListRow.Pressed`, a cell builder for `Table` with the cell's box and state, `ListState.RowHeight` and a header cell builder, `OutlineRows` with the row and its arrow, `GridState.Chosen` and `Element.IsSelected`, readable while painting.
- **Toolbars and fields.** A way to know a control is built in a toolbar and to style its items and overflow button, overlays that do not inherit the toolbar's look, and the field forwarding of `Combobox` (`Element.NameFrom`, `Element.FocusTo`) with an option not to highlight the first match.
- **MyGo's own strings.** An exported way to read the strings of its controls in the window's language, with an app's `mygo.*` overrides (its internal `l10n` package): with it, `DecimalInput`, `FindBar` and `ColorPicker` could be rebuilt from the bases MyGo already exports, and `Calendar` too but for `Browse`.
- **Paths.** `Path.ArcTo`, to stroke GTK's icons exactly.
- **Inputs.** The state of Caps Lock (a modifier bit or `Context.CapsLock`), for the caps-lock indicators of NSSecureTextField and GtkPasswordEntry; the character a password field hides its text with (`Element.PasswordChar`), for AppKit's and WinUI's larger dots; a way to take a button out of the Tab order (`Element.Focusable(false)`, as MyGo's own search field does for its clear button), so that a split button is one stop; and `Element.OpenMenu` on a menu button, so that the main part of a split button opens the menu with Alt+Down, as WinUI's does.
