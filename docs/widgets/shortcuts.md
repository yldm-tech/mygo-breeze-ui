# Shortcuts

The widgets of [`ui/breeze/widgets_shortcuts.go`](../../ui/breeze/widgets_shortcuts.go), whose catalog entries are [`ui/breeze/catalog/shortcuts.json`](../../ui/breeze/catalog/shortcuts.json). What every widget shares, its platforms, themes and limits, is in [Breeze UI for MyGo](../breeze-ui.md).

## Looks

| Widget | macOS | Windows 11 | GNOME |
|---|---|---|---|
| `ShortcutLabel`, `Keycaps` | one keycap holding the menu's glyphs (`⇧⌘T`): 22 points high, padded 8, corners of 6, 12-point text on black at 5% (white at 12%) with a 1-point shade along its bottom (inferred) | a keycap per key 4 apart, PowerToys's KeyVisual: padded 6, `ControlFillColorDefault`, 1-pixel `CardStrokeColorDefault` border, corners of 4, 12-pixel text | AdwShortcutLabel: a `.keycap` per key 6 apart, padded 6, at least 20 wide, currentColor at 10%, a 2-pixel inset `--card-shade-color` shade, corners of 6 |
| `ShortcutText` | the menu's key equivalent: `⌃⌥⇧⌘` then the key's glyph (`⇧⌘T`, `⌥⌘←`, `⌘↩`) | WinUI's KeyboardAccelerator text: Ctrl, Alt, Windows, Shift, then the key, joined by `+` (`Ctrl+Shift+T`) | GTK's accelerator label: Shift, Ctrl, Alt, Super, then the key, joined by `+` (`Shift+Ctrl+T`) |

## Sources

`ShortcutLabel(c, mods, key)`, `Keycaps(c, keys...)` and `ShortcutText(c, mods, key)` (`widgets_shortcuts.go`, with `TestScreenshotsShortcuts`) show keyboard shortcuts, from the `ui.Modifiers` and `ui.Key` an app binds with `Context.Shortcut`, so that the keys shown stay those handled. `ShortcutText` writes a shortcut as the platform's menus do, for a menu-like row or a tooltip; `ShortcutLabel` draws its keycaps, for a settings page or a cheat sheet; `Keycaps` draws keys given as text, for a chord or a range (`breeze.Keycaps(c, "[", "]")`). `ui.Cmd` stands for the command key of the platform drawn, Command on macOS and Ctrl elsewhere, so `ShortcutText(c, ui.Cmd|ui.Shift, ui.KeyT)` is `⇧⌘T` in a `Preview` of macOS and `Ctrl+Shift+T` in one of Windows on any host. Assistive technology hears a `ShortcutLabel` as one text named by the shortcut (`Shift Command T` on macOS, the text elsewhere) and a `Keycaps` by its keys separated by spaces; neither takes the focus, and the keycaps stay left to right in a right-to-left window, as AdwShortcutLabel keeps them. They come from:

- **macOS:** the order and glyphs of NSMenu's key equivalents (`⌃⌥⇧⌘`; `↩ ⎋ ⌫ ⌦ ⇥ ← → ↑ ↓ ↖ ↘ ⇞ ⇟`, Space and the function keys spelled out), which MyGo's own popover menus and GTK's macOS backend (`gtkaccelgroup.c`) write too. AppKit has no keycap control, so the keycap is inferred: one plate holding the whole shortcut, as macOS apps' settings and cheat sheets draw one.
- **Windows 11:** `KeyboardAccelerator::GetStringRepresentation` of microsoft-ui-xaml's main branch (`KeyboardAccelerator_Partial.cpp`), which a MenuFlyoutItem shows as its KeyboardAcceleratorTextLabel: Ctrl, Alt, Windows and Shift in that order, then the key, joined by `KEYBOARD_ACCELERATOR_TEXT_JOIN` (`%s+%s`), the keys named by the `TEXT_VK_` strings of `Microsoft.UI.Xaml.Common.rc` (Enter, Esc, Back, Delete, PageUp, Left, Space, Application) and the punctuation keys by the character the layout types. WinUI has no keycap control either; the keycap is PowerToys's KeyVisual (`Common.UI.Controls`) as its Keyboard Manager styles it (`OriginalKeyVisualStyle`: Padding 6, ControlFillColorDefault, a 1-DIP CardStrokeColorDefault border, ControlCornerRadius, FontSize 12, keycaps in a StackPanel of Spacing 4).
- **GNOME:** `gtk_accelerator_print_label` of GTK 4.24.0 for the text (Shift, Ctrl, Alt and Super in that order, joined by `+`; a character in upper case, Space, Backslash, else the keyval's name without underscores: Return, Escape, BackSpace, Page Up, Left), and libadwaita 1.10.0's AdwShortcutLabel for the keycaps (`adw-shortcut-label.c`: a keycap per key, Super, Ctrl, Alt and Shift in that order, arrows, `␣` and `⏎` as symbols; `_shortcuts-dialog.scss`: `.keycap` padded 6, at least 20 wide, corners of 6, `color-mix(in srgb, currentColor 10%, transparent)` with `inset 0 -2px var(--card-shade-color)`, and under `prefers-contrast: more` a 1-pixel ring of `--border-color`; the label's border-spacing of 6).

## Limits

Besides [those of every widget](../breeze-ui.md#limits):

- **Shortcuts.** The macOS and Windows keycaps are inferred, as neither platform has a keycap control: macOS's from the look of apps' settings and cheat sheets, Windows's from PowerToys rather than WinUI, and Windows's keys are text where PowerToys draws Segoe Fluent Icons' glyphs for the arrows, Enter, Back and Shift; no reference render compares them. `ui.Cmd` is read as the platform's command key, so where the host's Cmd is Super (macOS), a shortcut with `ui.Super` shows as Ctrl in a Preview of Windows or GNOME, and where it is Ctrl, one with `ui.Ctrl` shows as `⌘` in a Preview of macOS; on the platform itself every modifier keeps its name. The names are English, as WinUI's and GTK's are untranslated: Breeze UI cannot read the system's translations of them. AdwShortcutLabel spells Page_Up and Page_Down with the underscore when untranslated; Breeze UI writes Page Up and Page Down, as GTK's menus do. The punctuation keys show the character a US layout types, where WinUI asks the user's layout. Keys MyGo cannot report, as numeric keypad keys, and sequences and ranges, which AdwShortcutLabel joins with `→` and `⋯`, are left to `Keycaps`.
